misconfiguration disclosure

CVE-FAUX-0815-2

Not a CVE. Not a bees bug. Not NFS itself. A FAT32 boot hook that looks like “the AI gateway is down.”

What operators saw

After a NAS reboot the Unraid console printed Permission denied while a startup script ran. Clients could not mount the model pool. A desk-host Docker volume aimed at …:/mnt/ai-data/uv-cache failed with connection refused. The fast-models container was healthy. bees was still walking the pool inside the container.

The faulty line

( sleep 45; /boot/config/plugins/fast-models/host-nfs-export.sh ) &

Unraid /boot is FAT32. The script was -rw-------. After 45 seconds the shell tried to exec it. Permission denied. The persist script never ran: no host mount, empty /etc/exports, no nfsd.

Stopgaps that stole the session

rc.nfsd startDaemon up, export table empty

“NFS has been down for weeks”It was live in early August. It died on this reboot

The fix

( sleep 45; bash /boot/config/plugins/fast-models/host-nfs-export.sh ) &
bash /boot/config/plugins/fast-models/host-nfs-export.sh
showmount -e <nas-host-ip>
