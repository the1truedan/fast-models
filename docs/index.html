what it actually is

Two NVMe drives. One share. Background dedupe.

the pitch, short version

Four things it actually does

▣

Owns the drives

Privileged container, host kernel, two unassigned NVMes. Not a VM passthrough. Not an Unraid cache pool.

⬡

Shares identical extents

bees walks in the background. A 2G hash table is the default for multi-terabyte pools.

⇄

Exports once

Host nfsd on 2049. Array NFS stays off. Linux v4.2 and macOS v3 both work.

!

Survives reboot — if you use bash

Unraid /boot is FAT32. The persist script must be invoked with bash, or NFS dies after every restart.

Until it has its own host

This Unraid + host-nfsd layout is a stopgap. A dedicated box (or a small VM with the NVMe card passed through) would own Btrfs, bees, and nfsd without a FAT32 flash hook. Until that move: keep array NFS off, keep the container’s ENABLE_NFS=0, and keep the bash line in /boot/config/go.
